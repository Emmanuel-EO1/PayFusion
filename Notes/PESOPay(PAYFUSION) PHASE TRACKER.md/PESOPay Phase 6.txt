🧠 CORE PROBLEM SOLVED
❌ The Conflict
Database Constraint
Every Transaction MUST belong to a Business
Marketplace Reality
A cart can contain products from multiple businesses
User Expectation
User should pay once, not multiple times
💥 The Failure

Attempting to create a single transaction without a business caused:

IntegrityError
System crash due to NOT NULL constraint
✅ FINAL ARCHITECTURE (PRODUCTION-GRADE)
🏦 1. Treasury / Escrow System

We introduced a system-controlled business:

PayFusion Treasury (slug: payfusion-system)
✔ Purpose:
Acts as central receiver of all payments
Solves multi-vendor payment conflict
Enables clean financial tracking
🔁 CHECKOUT FLOW (Step-by-Step)
1. Cart Grouping

Cart items are grouped by business:

Business A → Items → Subtotal
Business B → Items → Subtotal
2. Master Transaction Creation
Transaction:
    user → customer
    business → PayFusion Treasury
    amount → TOTAL cart value
    status → pending

✔ This is the single payment entry point

3. Order Splitting

For each business:

Order:
    user → customer
    business → vendor
    transaction → master transaction
    total_amount → vendor-specific total
    status → pending

✔ One order per vendor
✔ All linked to ONE transaction

4. Order Items Creation

Each product becomes:

OrderItem:
    order → linked order
    product → product
    quantity → qty
    price → snapshot price
💳 PAYMENT PROCESSING FLOW
Step 1: Lock Transaction
select_for_update()

✔ Prevents double payment
✔ Ensures concurrency safety

Step 2: Verify Payment (Simulated)
payment_verified = True

(Will be replaced with Paystack in Phase 7)

Step 3: Atomic Ledger Update

Everything runs inside:

transaction.atomic()

✔ Either ALL succeed or ALL fail

Step 4: Update Master Transaction
txn.status = 'paid'
Step 5: Credit Treasury Wallet
credit_wallet(
    business=treasury,
    amount=txn.amount
)

✔ Represents real money entering platform

Step 6: Process Each Order

For every vendor order:

order.status = 'paid'
Step 7: Credit Vendor Wallets
credit_wallet(
    business=vendor,
    amount=order.total_amount
)

✔ Vendor receives their share
✔ Funds are now “virtually allocated”

💰 WALLET SYSTEM (LEDGER DESIGN)

Each Business has:

Wallet:
    balance
🔑 Important Principle

Wallet ≠ Raw Revenue
Wallet = Ledger Balance (after all operations)

✔ Why Wallet ≠ Revenue

Wallet includes:

Sales income ✅
Previous transactions ✅
Adjustments / test runs ✅
Withdrawals ❌ (deducted)
🏧 WITHDRAWAL SYSTEM
🎯 Goal

Allow vendors to withdraw funds safely

🔒 Step 1: Ownership Validation
Business must belong to request.user

✔ Prevents unauthorized withdrawals

🔍 Step 2: Input Validation
Decimal conversion
amount > 0

✔ Prevents invalid or malicious input

🔐 Step 3: Row Locking
Wallet.objects.select_for_update()

✔ Prevents race conditions
✔ Ensures accurate balance updates

⚖️ Step 4: Balance Checks
vendor_wallet >= amount
treasury_wallet >= amount

✔ Ensures system integrity

🔻 Step 5: Debit Vendor Wallet
debit_wallet(vendor)
🔻 Step 6: Debit Treasury Wallet
debit_wallet(treasury)

✔ Represents actual cash leaving platform

🧾 Step 7: Log Transaction
Transaction:
    type → withdrawal
    status → pending

✔ Enables audit trail

🔁 CONCURRENCY SAFETY (CRITICAL)
Tools Used:
transaction.atomic()
select_for_update()
F() expressions
Idempotency checks (status != 'pending')
✔ What This Prevents:
Double payments
Double withdrawals
Race conditions
Data corruption
